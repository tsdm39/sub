## 四、各岗红线

### 翻译
- **只填 `对白 中文` 样式**，其余样式一律不碰
- **日语列一个字都不能改**
- 存盘保持 **UTF-8**，编码一变整集报废
- 提交走分支 + PR，**不要直接改主干**

### 轴
- 只改时间码与断句，不动他人样式的文本

### 场面文本 / 特效 / 遮罩
- 归属 `场面文本`、`遮罩`、`标题`、`声明` 等样式
- 时长下限：**≥ 12 帧（24fps 下约 0.5 秒）才值得做**
- ⚠️ 但**过下限 ≠ 全做**：0.54 秒内观众只能读 5~6 字，信息密度要另行筛选

### 压制
- 交片进仓库后**知会监制与翻译**（两边都要拿代理对轴 / 试轴）

### 全岗
- 数字、金额、英文词、人名：**当场写进术语表，不要留在脑子里**
- 听不清的标 `⚠️听不清`，**禁止硬猜**（本作后段无 CC，纯听段落必须双人听校）

## 六、进度巡检机制（本组不设交片死线）

> 全员均为**业余时间**参与，本组**不设交片死线、不追进度百分比**。
> 取而代之：由监制在**新片源到达时**做一次巡检，判断上一集卡在哪一步，**只提醒对应岗位**。

**巡检时机**：每周四（新一集片源日）
**巡检对象**：上一集（例：10/08 ep2 出片源 → 巡检 ep1）

**巡检方法**：
1. 看 `工作稿件/FX/` 下五个目录里，**哪个阶段有该集的文件**
2. 已完成的**最后一个阶段 → 下一个阶段即卡点**
3. 检查是否有**未合并的 PR**（那属于监制自己的锅）
4. 检查**最终稿件**目录

**卡点判定 → 提醒对象**：

| 判定 | 提醒岗位 |
|---|---|
| `1.空轴稿件` 无文件 | 空轴（椎名るり） |
| 有 1，`2.翻译稿件` 无 | **翻译（巡）** |
| 有 2，`3.时轴稿件` 无 | 轴（kuzu / 小花） |
| 有 3，`4.校对稿件` 无 | 校对（Aurora.Akie / 椎名るり） |
| 有 4，`5.后期稿件` 无 | 后期（椎名るり） |
| 有 5，`最终稿件` 无 | **压制（240557498）** |
| 存在未合并 PR | 监制（猫又弐號） |

**提醒口径**：只报「**差哪一步、在谁手上**」，不催、不谈百分比、不设时限。

## 七、已知风险（监制记录）

1. **翻译产能 < 一集周期**
   一集翻译量 2957 字（第 1 话实测）；新人速度 150~250 字/时 → 需 12~20 小时；且翻译只有晚间可用。
   → **每集缓冲不足，一集延迟即全季顺延。**
   → 对策：先测速（前 30 条约 350 字），据实测决定是否**分 P**。

2. **后期单点故障**
   后期目前只有 1 人。12 周内任何一次意外都会导致整条线停摆。
   → 对策：第 3~4 话起指定一人跟进后期流程，作为备份。
